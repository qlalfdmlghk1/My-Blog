# Taxonomy Domain Language

글을 분류하는 두 축(카테고리 · 태그)과 그 표기를 다룬다.

## Language

**카테고리 (Category)**:
글이 **무슨 성격의 글인가**를 답하는 축 — 관리 화면에서 만들고, 글 1편은 정확히 1개를 가지며, 색을 가진 유일한 분류다.
_Avoid_: "대분류", "메인 태그", "컬러 태그". 코드는 `category` 유지.

**팔레트 슬롯 (Palette slot)**:
카테고리에 배정할 수 있는 색 한 벌 — 라이트/다크 배경·글자 네 값이 짝지어진 단위이며 코드에 12개로 고정된다.
_Avoid_: "테마 컬러", "카테고리 색상값". 카테고리 문서에는 hex 가 아니라 슬롯 ID 만 저장한다.

**태그 (Tag)**:
글에 **무엇이 나오는가**를 답하는 축 — 기술 · 도구 · 스펙의 고유명사만 받고, 개수 제한 없이 붙으며, 색을 갖지 않는다.
_Avoid_: "키워드", "해시태그". 저장값에 `#` 을 넣지 않는다(화면에서 `TagChip` 이 붙인다).

**소주제**:
카테고리 안에서 글을 다시 묶는 단위 — 별도 필드가 아니라 **그 카테고리의 글에 붙은 태그**로 표현한다.
_Avoid_: "서브카테고리", "중분류" — 스키마에 그런 필드는 없다.

**발행 / 임시**:
공개 여부 — `published` 는 블로그에 노출되고, `draft` 는 관리자에게만 보인다.
_Avoid_: "공개/비공개", "게시/미게시". 코드는 `status: 'published' | 'draft'` 유지.

## Relationships

- 한 글은 카테고리를 정확히 1개, 태그를 0개 이상 가진다.
- 태그는 카테고리에 속하지 않는다 — 같은 태그가 여러 카테고리의 글에 붙을 수 있다(`#Next.js` 가 `프론트엔드` 글에도 `트러블슈팅` 글에도).
- 계층은 2단(카테고리 → 글)이다. 화면에 3단으로 보이더라도 그건 카테고리별로 태그를 집계해 그린 것이지 저장 구조가 아니다.

## Naming decisions

- 카테고리의 **정본은 Firestore `categories` 컬렉션**이고, 문서 ID 가 곧 slug 다. `src/lib/categories.ts` 에 남은 배열은 컬렉션이 비었을 때 쓰는 기본값일 뿐이다.
- slug 는 만들 때 한 번 정하고 이후 바꾸지 않는다 — 바꾸면 발행된 카테고리 URL 과 글의 `category` 참조가 함께 끊긴다.
- 색 값의 **단일 진실 공급원은 `src/lib/palette.ts`** 다. 화면 CSS 변수(`--pal-{slot}-*`)와 OG 이미지 색이 모두 이 값에서 파생된다.
- **카테고리 이름을 태그로 쓰지 않는다.** `프론트엔드` `성능` 은 카테고리가 이미 말하고 있어, 태그로 두면 두 축이 같은 것을 가리켜 태그가 아무것도 구분하지 못한다. 판정 재료는 `categoryWordSet()`, 화면 경고는 `PostEditor`.
- 태그 표기는 통용되는 공식 표기를 그대로 쓴다 — `Next.js`(`nextjs` 아님), `ISR`, `Firestore`.

## Flagged ambiguities

- **태그가 카테고리를 복사하던 문제**: 첫 글의 태그가 `#프론트엔드` 로, 카테고리 이름을 `#` 까지 붙여 되풀이하고 있었다 — resolved: 태그는 고유명사(기술·도구·스펙 이름) 전용으로 확정. `#` 은 입력에서 벗겨내고, 카테고리 이름과 겹치는 태그는 에디터가 경고한다.
- **카테고리가 코드 상수였던 시기**: v1 은 `categories.ts` 배열이 정본이라 카테고리를 늘리려면 코드 수정 + `firestore.rules` 의 하드코딩 목록 수정 + 규칙 재배포가 함께 필요했고, 규칙을 잊으면 저장이 조용히 막혔다 — resolved: Firestore 로 옮기고 규칙은 목록 대신 `exists()` 로 카테고리 문서 존재를 확인한다.
- **"소주제"의 정체**: 카테고리 아래 한 층을 더 둘지 검토했다 — resolved: 필드를 추가하지 않고 태그로 표현한다. 소주제를 필드로 못 박으면 교차 주제(여러 카테고리에 걸친 기술)를 한 곳에만 둘 수 있게 되고, 글이 적은 시점에 빈 소주제가 노출된다. 한 카테고리의 글이 한 화면을 넘어설 때 재검토한다.
