### 기획서 결정 번복 — 좌측 분류 내비

[docs/PLAN.md](../../PLAN.md) 「디자인 방향 › 레이아웃」은 v1에서 좌측 트리를 쓰지 않기로 했다.
근거는 "레퍼런스의 좌측 카테고리 트리는 글 872개라서 성립하는 구조. 글 3편에 적용하면 빈 공간이 드러남"이었다.

그 판단은 **태그 기준**이었다. 태그는 자유 증식이라 글이 적으면 목록이 빈약해진다.
반면 **카테고리는 6개로 고정**이라 글 수와 무관하게 항목이 항상 6줄이다.
872개짜리 트리를 흉내 내는 게 아니라 6줄짜리 고정 목록이므로 빈 공간 문제가 생기지 않는다.
글이 0편인 카테고리는 자리는 지키되 링크를 걸지 않고 흐리게 처리한다.

## 🛠️ 접근 방식

- 카테고리 목록·필터는 Firestore 복합 색인을 늘리지 않고 `getPublishedPosts()` 결과를 메모리에서 집계·필터한다 (기존 `getAllTags` 와 동일 방식). 글이 세 자리를 넘으면 쿼리 + 색인으로 전환한다.
- 사이드바는 `ListShell` 한 곳에서 조립해 홈·카테고리·태그 세 화면이 공유한다. 라우트마다 따로 조립하면 카테고리를 늘릴 때 고칠 곳이 세 군데가 된다.
- 목차는 서버 컴포넌트로 두고 앵커 이동만 지원한다 (공개 페이지 클라이언트 JS 0KB 유지). 스크롤 위치 추적 하이라이트는 전송 비용 대비 값어치가 낮아 제외.
- 폰트는 CDN + `font-display: swap` + `preload`. 렌더 차단은 막되 전송량은 실측 후 판단한다.

## ✅ 검증 계획

- 단위/통합 테스트: 테스트 스크립트 없음 — `npm run typecheck` · `npm run lint` · `npm run build` 로 대체
- 회귀 포인트
  - `renderMarkdown()` 반환 타입이 `string` → `{ html, toc }` 로 바뀌었다. 호출부는 글 상세 한 곳
  - `revalidatePost()` 에 `categories` 인자가 추가됐다. 미전달 시 카테고리 페이지가 낡은 채로 남는다
  - `TagFilter` 삭제 — 남은 import 가 없어야 한다
  - `max-w-shell` 이 60rem → 76rem 으로 바뀌어 기존 목록 화면 폭에 영향
- 수동 확인
  - 홈 · 카테고리 6개 · 태그 · 글 상세에서 사이드바 활성 표시가 맞는지
  - 글이 0편인 카테고리가 링크 없이 흐리게 표시되는지, 목록 밖 slug 가 404 인지
  - 글 상세에서 목차 앵커 이동 (h2·h3 3개 이상일 때만 노출)
  - 좁은 화면에서 사이드바가 본문 위로 흐르는지
  - 발행 → `/categories/{slug}` 가 실제로 재생성되는지
  - 다크 모드에서 카테고리 색 점·인용 박스 대비
- 성능: 배포 후 Lighthouse 실측. 폰트 838KB 가 LCP·점수에 미치는 영향을 보고 폰트 전략 확정
