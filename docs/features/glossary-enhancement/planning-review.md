## ⚠️ 반드시 확인 (7건)

#### A. 글 하단 "관련 용어" 목록의 출처와 저장 방식 *(신규)*

- **분류**: 미정의 케이스
- **근거**: 자동 링크는 렌더 시 본문에서 찾아 붙는다(`splitByGlossary`, `markdown.ts:78`). 글 문서(`posts/{id}`)에는 용어 참조 필드가 없다.
- **확인 질문**: 관련 용어 목록은 ① **본문에 실제로 자동 링크된 용어 전부**인가요, ② **이 글에서 AI로 추출·등록한 용어**만인가요? 렌더할 때마다 본문에서 계산하나요, 글 문서에 `termSlugs` 같은 필드로 **저장**하나요? 링크 대상은 `/glossary#{slug}` 인가요?

#### B. 새 용어 등록 후 이미 발행된 글의 반영 시점 *(미해소 — 재질문)*

- **근거**: 자동 링크와 관련 용어 섹션 모두 서버 렌더 결과 HTML에 박힌다. 재검증은 경로 단위(`api/revalidate`).
- **확인 질문**: 새 용어가 **이전에 발행한 글**의 본문 링크·관련 용어에도 나타나야 하나요? 그렇다면 등록 시 전체 재검증이 필요하고, 아니면 각 글을 다시 수정할 때 반영됩니다. 어느 쪽인가요?

#### C. 확인 페이지에서 "발행 확정"과 저장 시점

- **근거**: 현재 `save('published')` 가 Firestore 쓰기 + `revalidatePost` 를 한 번에 한다(`PostEditor.tsx:213-271`).
- **확인 질문**: 확인 페이지 진입 시점에 글이 **이미 발행 저장**된 상태인가요, **확정 버튼을 눌러야 발행**인가요? 확인 페이지에서 이탈·뒤로가기 하면 작성 내용은 어떻게 되나요? 추출이 끝나지 않아도 발행할 수 있나요?

#### D. 보안 규칙 필수 필드 추가와 마이그레이션 순서

- **근거**: `firestore.rules:102` `validGlossaryTerm` 이 create/update 를 모두 검증한다. 필수 필드를 먼저 추가하면 **값이 없는 기존 문서는 수정이 막힌다.**
- **확인 질문**: 마이그레이션(기존 용어에 분류 채우기) → 규칙 배포 순서로 진행하는 게 맞나요? 마이그레이션은 **스크립트**(기존 `scripts/set-admin-claim.mjs` 같은 방식)인가요, 관리 화면에서 손으로 채우나요?

#### E. 용어 전용 분류의 데이터 모델

- **근거**: 글 카테고리는 `categories/{slug}` + 팔레트 슬롯 ID(`types/category.ts`). 용어 분류도 비슷한 모양이 될 것으로 보이나 미정.
- **확인 질문**: 분류에 **색(팔레트 슬롯)** 과 **정렬 순서**를 두나요? 용어 1개당 분류는 정확히 1개인가요? 분류를 지울 때 그 분류에 속한 용어는 어떻게 되나요?

#### F. Gemini 모델·호출 한도·비용

- **확인 질문**: 어떤 모델인가요? 무료 티어의 분당/일일 한도에 걸렸을 때 화면은 어떻게 반응하나요? 긴 글에서 토큰 한도를 넘으면 본문을 잘라 보내나요?

#### G. 추출 용어의 slug 생성 규칙과 실패 처리 *(미해소)*

- **근거**: 용어 slug 은 문서 ID이자 `/glossary#{slug}` 앵커라 이후 변경 불가(`types/glossary.ts`). 발행 slug 은 로마자 변환(`src/lib/romanize.ts` · `slug.ts`).
- **확인 질문**: 영문·한자·기호 섞인 용어의 slug 은 어떻게 만드나요? 로마자화 실패나 중복 시 사람에게 입력을 요구하나요, 자동 suffix 인가요?

#### H. AI 호출 실패·타임아웃·결과 0건일 때의 화면 *(미해소)*

- **확인 질문**: 실패 시 무엇을 보여주나요(토스트/인라인)? 재시도·취소를 두나요? 추출 0건일 때 문구는요?
