- [2026-08-29] **관련 용어의 출처**: 본문에 **실제로 링크가 걸린 용어**만. `renderMarkdown()` 이 링크를 건 slug 목록을 함께 돌려주고 글 상세가 그걸 쓴다. 글 문서에 저장하지 않는다 — 링크가 렌더 시점에 붙으므로 저장하면 본문과 목록이 갈라진다.
- [2026-08-29] **기존 발행 글 반영**: 용어를 등록하면 기존 `revalidateGlossary()` 를 그대로 호출해 **발행 글 전체를 재검증**한다. 이미 있던 정책이고(자동 링크가 렌더 시점에 붙는 구조 때문), 새 경로를 만들지 않았다.
- [2026-08-29] **확인 페이지의 저장 시점**: 에디터가 **먼저 저장하고** 문서 ID 로 넘긴다 → 이탈해도 내용이 남는다. 상태는 올리지 않는다(새 글은 draft, 발행 글은 published 유지). `published` 로 바꾸는 것은 확인 페이지의 확정 버튼 하나뿐 — 수정 중이던 발행 글이 확인 화면을 여는 동안 내려가면 안 되기 때문.
- [2026-08-30] **마이그레이션 불필요**: 애초 "값을 먼저 채우고 규칙을 배포한다"는 순서를 잡고 스크립트까지 만들었으나, Firestore 를 실제로 조회해보니 **용어·분류 문서가 0개**였다. 잠길 기존 문서가 없어 스크립트와 `glossary:migrate` npm 스크립트를 제거했다. 앞으로 등록되는 용어는 처음부터 분류를 갖는다.
- [2026-08-30] **발견한 버그**: 위 스크립트를 만들 때 `privateKey.replace(/\n/g, '
')` 의 백슬래시가 하나 삼켜져 `/
/g` 로 저장돼 있었다. 그대로 돌렸으면 개인키 파싱이 `DECODER routines::unsupported` 로 실패했을 것이다(`seed-categories.mjs` 와 대조해 발견). 스크립트 자체는 제거했지만, 같은 방식으로 파일을 쓸 때 조심할 것.
- [2026-08-29] **분류 데이터 모델**: `glossaryCategories/{slug}` = `name` · `palette`(팔레트 슬롯 ID) · `order`. 용어 1개당 1개. **규칙에서 분류의 존재는 검사하지 않는다** — 글 카테고리와 달리 URL 을 이루지 않아 없는 값을 가리켜도 미분류로 떨어질 뿐이고, `exists()` 를 걸면 분류를 지운 뒤 그 용어의 수정 자체가 막힌다. 소속 용어가 남은 분류의 삭제는 화면이 막는다.
- [2026-08-29] **Gemini 호출**: 기본 모델 `gemini-2.5-flash`(`GEMINI_MODEL` 로 교체 가능), REST 직접 호출이라 SDK 의존성 추가 없음. 키는 `x-goog-api-key` 헤더로 — URL 은 로그에 남는다. 본문 20,000자 상한(초과 시 잘렸음을 화면에 알림), 후보 최대 12개, `responseSchema` 로 JSON 강제, temperature 0.2. 429 는 "한도 초과, 잠시 뒤 재시도"로 따로 안내.
- [2026-08-29] **추출 용어의 slug**: 기존 `toAsciiSlug` 재사용(표제어를 고치면 따라오고, 손대면 멈춤). 만들지 못하면 사람에게 직접 입력을 요구하고, 중복은 등록 직전 `isGlossarySlugTaken` 으로 막는다(후보끼리 겹치는 것도 먼저 검사).
- [2026-08-29] **실패·0건 처리**: 인라인 오류 문구 + `다시 뽑기` 버튼. 0건은 "이미 다 있음"과 "뽑힌 게 없음"을 구분해 안내. 추출과 무관하게 발행 확정은 언제든 가능(추출은 발행의 전제가 아니다).
- [2026-08-29] **검색 방식**: 전체 목록을 내려 **클라이언트에서 필터**. 초성 검색은 표제어·별칭에만 적용(정의문까지 초성으로 훑으면 두세 글자에 거의 전부가 걸린다). 검색·필터 상태는 **URL 에 반영하지 않는다** — 첫 렌더가 전체 목록이라 SSR·SEO·`#slug` 앵커가 그대로 살아 있다.

**결정 로그**

- 용어 분류는 **선택 필드**다. 필수로 두면 낱말을 급히 넣는 자리에서 아무 분류나 고르게 되고, 그 값이 나중에 진짜 분류처럼 보인다. 비워 두면 '분류 없음'으로 모여 손볼 대상이 오히려 드러난다.
- 관련글·관련 용어는 **저장하지 않는다**. 링크가 렌더 시점에 붙으므로 저장하면 본문과 목록이 갈라진다. 같은 색인(`buildDictionaryIndex`)으로 판정한다.
- slug 은 AI 경로에서만 영어로 받는다. 로마자를 택했던 근거(키·비용·비결정성)가 **사람이 버튼을 누르는 경로**에는 해당하지 않기 때문이고, 실패해도 기존 로마자 값이 남아 잃는 게 없다.
- 데이터 마이그레이션은 하지 않았다 — Firestore 를 조회해 네 컬렉션 모두 0건임을 확인했다. 만들었던 스크립트는 제거했다.

- **부분 등록 수정**: 용어 일괄 등록에서 중복 검사를 쓰기 **전에 전부** 끝내고, 실제로 저장된 건수를 추적해 한 건이라도 썼으면 화면 정리와 재검증을 반드시 수행한다. 이전에는 k번째에서 실패하면 앞의 k-1개가 저장된 채 화면·재검증이 건너뛰어져, 다시 누르면 자기가 만든 용어에 "이미 사용 중"으로 막혔다.
- **발행 검증 추가**: `/admin/publish/[id]` 는 주소로 직접 들어올 수 있는데 검증이 없어 본문이 빈 글도 발행됐다. 최소 기준(제목·본문·slug·분류)을 확인한다.
- **응답 계약 단일화**: `ExtractedTerm`·`SkippedTerm`·`ExtractResponse` 를 `types/dictionary.ts` 한 곳으로. 라우트와 클라이언트가 각자 선언하면 서버가 필드를 바꿔도 타입 에러 없이 런타임만 갈라진다.
- **라우트 중복 제거**: `PostLoader` 를 만들어 편집·발행 확인 두 라우트가 공유. 60줄 복사가 사라졌다.
- **관련글 판정 정확도**: `stripNonProse` 로 코드·제목·링크 주소를 걷어낸다. 렌더러는 그 자리에 링크를 걸지 않는데 역참조만 세고 있어, 점선이 없는 글이 관련글에 뜨는 어긋남이 있었다.
- 그 밖에: Gemini fetch 타임아웃(25초), slug sanitize 후 문서 ID 사용, 별칭 길이 상한, 컬렉션 상수·검증 함수 공용화, 저장/재검증 분리, `/admin/glossary` 리다이렉트, 죽은 `hasGeminiKey` 제거.
- **포맷 노이즈 복구**: `.prettierrc`(singleQuote·printWidth 100) 추가. 설정이 없어 훅의 prettier가 기본값(큰따옴표)으로 두 파일을 전면 재포맷했고, PostEditor diff 264줄 중 대부분이 그 노이즈였다 → 112줄로 줄었다.

**결정 로그**

- 자동 반영은 Blocker·명백한 기능 오류·검증 실패로 제한했다. 기본 선택 상태(`selected: true`), Gemini 에러 원문 노출, rate limit, 인증 헬퍼 추출은 정책·범위 판단이라 남겼다.
- 규칙 미배포는 코드로 못 고치는 배포 작업이라 사람에게 남긴다.
