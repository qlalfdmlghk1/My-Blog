## 🚫 개발 착수 불가 (3건)

#### 1. "토스처럼"의 적용 범위가 정의되지 않음

- **분류**: 미정의 케이스 (범위 경계)
- **근거**: plan.md 🎯/📋 는 "모바일 레이아웃 깨짐 해결"인데, 참고 자료로 받은 toss.tech 스크린샷은 *레이아웃 수정*이 아니라 *다른 정보 구조*다. 현행 `PostCard.tsx:31` 은 썸네일 없는 `border-b` 목록, `SiteHeader.tsx:50-65` 는 텍스트 내비, `ListShell.tsx:36` 은 분류 사이드바 2단 — 셋 다 레퍼런스에 대응물이 없거나 형태가 다르다.
- **확인 질문**: 토스 스크린샷은 **(A) 모바일 여백·글자 크기의 "밀도 레퍼런스"** 인가요, **(B) 카드·헤더 구조까지 바꾸는 "구조 레퍼런스"** 인가요? (B)라면 이 작업은 Refactor가 아니라 Feat/Redesign에 가까워 Type·범위를 다시 잡아야 합니다.
- **권장 방향(참고 — 사람 확인 필요)**: 커밋 이력상 `blog-ui-redesign`·`project-wide-refactor`가 이미 끝난 상태라 현 디자인에 누적된 판단(주석에 근거가 길게 남아 있음)이 많습니다. (A)로 좁히면 그 판단을 보존한 채 이번 PR을 닫을 수 있습니다.

#### 2. 모바일 헤더 내비의 목표 형태가 미정 — 이 사이트엔 "검색"이 없음

- **분류**: 미정의 케이스 / 흐름 누락
- **근거**: 레퍼런스 헤더는 `로고 + 검색 + 햄버거` 3요소다. 현행 `SiteHeader.tsx` 는 `로고 + '글' + '용어' + 구분선 + ThemeToggle` 이며, **전역 검색 기능은 이 레포에 존재하지 않는다**(`src/app` 에 검색 라우트 없음).
- **확인 질문**: 모바일 헤더를 ① 지금처럼 텍스트 링크 유지(간격만 조정) ② 햄버거 메뉴로 접기 ③ 검색까지 신규 구현 — 어느 쪽으로 갈까요? ③은 이번 범위(Refactor) 밖으로 보이는데, 별도 이슈로 분리해도 될까요?
- **권장 방향(참고 — 사람 확인 필요)**: 링크가 2개뿐이라 햄버거의 이득이 크지 않을 수 있습니다. 다만 ②를 고르면 신규 `'use client'` 컴포넌트가 생기므로 In Scope에 명시가 필요합니다.

#### 3. 카드 썸네일 도입 여부와 `coverImage` 없는 글의 표시 규칙이 미정

- **분류**: 미정의 케이스 (경계값)
- **근거**: 레퍼런스 목록은 **대형 썸네일이 카드 골격**이다. `types/post.ts:23` 의 `coverImage: string | null` 이라 없는 글이 존재할 수 있고, 현행 `PostCard.tsx` 는 썸네일을 아예 그리지 않는다. 발행된 글 중 커버 이미지 보유 비율은 이번 검수에서 확인하지 못했다(`추측:` 상당수가 null일 가능성).
- **확인 질문**: 목록 카드에 썸네일을 넣을까요? 넣는다면 `coverImage`가 `null`인 글은 ① 썸네일 영역 자체를 생략(높이 가변) ② 무채색 플레이스홀더 ③ 카테고리 색 기반 자동 생성 — 어느 쪽인가요? (①은 목록이 들쭉날쭉해지고, ②/③은 신규 에셋·로직이 필요합니다.)
