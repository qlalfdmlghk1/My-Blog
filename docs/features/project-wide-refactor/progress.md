  고칠 때마다 글 본문을 다시 써야 하고, 지운 용어의 링크가 화석으로 남는다

- 제목·링크 안은 끈다. 중첩 `<a>` 는 무효이고, 제목에 걸면 목차와 본문 모양이 갈린다
- **사전 변경 = 발행 글 전량 재생성.** 어느 글에 그 낱말이 있는지는 본문을 다 훑어야

- `aliases` 를 10개로 묶었다 — 열어두면 표기 수천 개짜리 문서 하나로 글 렌더링마다
  거대한 정규식이 만들어진다. 화면이 아니라 **규칙**에서 막는다
- 점선 밑줄 — 실선+굵게는 "나간다"로 읽힌다. 점선은 사전의 관용 표시라 "참조"로 읽힌다

**결정 로그**

- 대비 수치를 **4.58 → 4.54 로 정정**했다. QA 가 WCAG 상대휘도로 실측한 값이 4.5377 이다.
  AA(4.5:1)는 통과하지만 **여유가 0.04 뿐**이라는 사실도 주석에 함께 남겼다
- `/api/revalidate` 의 전량 무효화 **근거를 고쳤다.** "어느 글인지 찾는 게 비싸서"가
  아니다 — `getPublishedPosts()` 가 이미 본문까지 읽어왔고 `strip` 이 메모리에서 버릴 뿐이라
  표적 탐색의 추가 읽기는 **0회**다. 진짜 근거는 `revalidatePath` 가 **무효화 표시만 하고
  재생성은 요청 시점까지 미룬다**는 것. 틀린 근거는 다음 판단을 잘못된 방향으로 이끈다.
  전환 시점도 숫자로 못 박았다 — **글 수 × 용어 수 ≳ 8,000**
- `splitByGlossary` 의 "정규식이 모듈 스코프에 캐시된다" 는 사실이 아니다.
  `buildGlossaryIndex` 는 `renderMarkdown` 호출마다 돈다. **코드는 맞고 이유가 틀렸다**
- `renderMarkdown` JSDoc 이 근거로 든 "OG 이미지 등" 호출부는 **존재하지 않는다**.
  호출부는 글 상세 한 곳뿐이다. 기본값은 남기되 실제 이유(전문 RSS 대비)로 고쳐 적었다
- `romanize.ts` 에 `hangulChoseong` 이 함께 있는 이유를 docblock 에 적었다 — 공유하는 것은
  "로마자화"가 아니라 **음절 분해**라는 원시 연산이고, 쪼개면 초성 인덱스가 어긋날 수 있다

**남긴 항목 (자동 반영 안 함)**

- 🔴 **기존 글의 slug 을 바꾸면 옛 `/posts/{old}` 가 무효화되지 않는다** — 재생성 API 계약
  변경(`slugs: string[]`)이 필요. 직전 릴리스에서도 같은 항목이 남았다. 용어 사전은 정반대로
  slug 입력을 `disabled` 로 잠갔으므로 **두 화면의 정책이 갈려 있다**
- **원시 HTML `<a>` 안에서는 용어 링크가 억제되지 않아 중첩 `<a>` 가 생긴다** —
  `suppressGlossary` 는 마크다운 `link`·`heading` 에서만 오른다. 렌더러 상태 설계 판단
- **`firestore.rules` 가 문서 ID 와 `aliases` 원소를 검증하지 않는다** — `hasAll` 은 추가
  필드를 막지 않고, 별칭은 개수만 보고 각 원소의 타입·길이는 자유다. 보안 규칙 변경
- **공개 `/glossary` 가 미발행 초안 글의 slug 을 노출한다** — `postSlug` 는 의도적으로 글의
  존재를 확인하지 않는다(초안 미리 잇기). 그 의도와 충돌하는 정책 판단
- **`scope==='glossary'` 일 때 카테고리·소분류·태그 순회를 건너뛸 수 있다** (73 → 31 경로) —
  사전 편집은 목록의 글 수·분류 트리를 바꾸지 않는다. 재생성 동작 변경이라 사람 확인
- **`getGlossaryAnchors()` 가 정의문 전량을 받아온다** — `.select('term','aliases')` 로 줄일
  수 있으나 필드 누락 시 조용히 비므로 사람 확인. 과금 문서 수는 안 줄고 페이로드만 준다
- **`React.cache()` 미사용** — 글 상세 한 장이 Firestore 왕복 4회(`2+C+G` 문서). 직전
  릴리스에서도 남긴 항목
- **자동 링크 정규식 총량 상한 없음** — 용어 문서 수에 상한이 없다. ReDoS 는 아니다
  (`escapeRegExp` 적용 확인). 상한값은 사람이 정할 값
- **영문 뒤 조사가 붙으면 slug 에서 두 낱말이 붙는다** (`React를` → `reactreul`) —
  로마자 출력 규칙 변경이라 기존 글의 재생성 결과가 달라진다
- `/glossary` 페이지네이션은 **넣지 않는 게 맞다** — 본문 앵커(`/glossary#slug`)가 "한 문서
  안에 있다"를 전제한다. 아키텍트 판정, 조치 없음
