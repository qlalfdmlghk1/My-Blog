# project-wide-refactor — tech 기록

## [2026-08-27] 용어 사전을 독립 페이지로 분리하고 본문에서 자동 링크 (#9)

**저장된 본문을 건드리지 않는다**

용어 링크를 마크다운 원문에 박아 넣는 방법도 있었지만 쓰지 않았다. 그러면 용어 하나를
고칠 때마다 그 낱말이 든 **글 본문을 전부 다시 써야** 하고, 사전에서 지운 용어의 링크가
본문에 화석으로 남는다. 링크는 **렌더 시점**에 붙인다(`lib/markdown.ts`). 저장된 것은
언제나 사람이 쓴 마크다운 그대로다.

대가는 재생성 범위다 — 아래 참조.

**`text` 렌더러에서만 링크를 건다**

marked 의 `text` 토큰은 **이스케이프 전 원문**으로 넘어오고 렌더러가 이스케이프한다.
그래서 용어 탐색도 그 원문 위에서 해야 한다. 이스케이프된 문자열에서 찾으면 `&amp;` 가
낀 표기를 놓친다. 인라인 코드는 `codespan` 렌더러가 따로 받으므로 애초에 여기 오지 않는다 —
코드 안의 낱말에 링크가 걸리는 사고가 구조적으로 막힌다.

**끄는 구간을 플래그로 잡는다**

제목과 링크 안에서는 링크를 걸지 않는다.

- **링크 안**: 중첩 `<a>` 는 유효하지 않아 브라우저가 태그를 끊는다
- **제목 안**: 목차 항목과 본문 제목의 모양이 갈린다

`suppressGlossary` 카운터를 `heading` · `link` 렌더러가 올렸다 내린다. marked 의 파싱은
렌더러 안에서 **동기로** 끝나므로 이 플래그만으로 구간이 정확히 잡힌다(비동기였다면
구간이 섞였을 것이다).

**한 글에서 같은 용어는 첫 등장만**

`linkedTerms` Set 으로 막는다. 전부 걸면 흔한 낱말이 한 문단에 대여섯 번 점선으로 깔려
본문이 읽히지 않는다.

**사전이 바뀌면 발행된 글이 전부 다시 만들어진다**

링크가 렌더 시점에 붙는 대가다. 용어를 하나 추가하면 그 낱말이 들어간 모든 글의 HTML 이
낡는데, **어느 글에 들어 있는지는 본문을 전부 훑어야만 알 수 있다.** 글 수가 수십 편
규모인 개인 블로그라 전량 재생성이 그 탐색보다 싸고 확실하다고 판단했다.
`scope: 'glossary'` 로 재생성 라우트에 그 범위를 알린다.

> 글이 수백 편이 되면 이 판단을 뒤집어야 한다. 그때는 글마다 "쓰인 용어" 역색인을
> 저장해 두고 해당 글만 무효화하는 쪽이 맞다.

**보안 규칙 — `aliases` 개수를 묶어둔 이유**

`aliases` 는 본문 자동 링크가 훑는 목록이다. 열어두면 표기 수천 개가 든 문서 하나로
**글 렌더링마다 거대한 정규식**이 만들어진다. 정의문 길이(600)와 표기 수(10)는 그래서
규칙 레벨에서 제한한다 — 관리 화면만 막으면 규칙을 우회한 쓰기로 뚫린다.

`postSlug` 는 존재까지 확인하지 않는다. 초안 상태의 글을 미리 이어둘 수 있어야 하고,
끊긴 링크는 404 로 끝난다.

**점선 밑줄로 그린 이유**

일반 링크와 같은 실선 + 굵게를 쓰면 "다른 글로 나간다"로 읽힌다. 점선 밑줄은 사전에서
**'뜻풀이가 있다'는 관용 표시**라, 이동이 아니라 참조로 읽힌다. 글자색은 본문 그대로 둔다 —
흐리게 하면 본문 대비가 링크마다 들쭉날쭉해진다.
